# 按需栈帧与重复处理器合并（2026-11-09）

> 历史记录：原来的 10 项业务内存差异已在 [独立内存修复](../verification_memory/README.md) 中消除。

基线是完整提交 `ff0d110c7ec2dbeb63ecb11f3780731f3357fc1e`，通过独立工作目录、独立 Python 进程构建，避免把当前 core 与旧解释器混用。环境：macOS arm64、Python 3.9.6、Node.js v24.19.0、WABT 1.0.39。

## 先修复栈帧

原实现每次调用固定向下预留 1024 字节，操作数却向上增长。子函数栈超过预留区域时会覆盖调用者数据：原始 WASM 返回 7，而保护版返回 0。原先 20 类/60 次构建测试中有 42 次失败，摘要保存在 before_stack_summary.json。

现在从可达 AST 的完整类型栈计算各函数峰值（含两侧分支、调用返回值），向上对齐到 16 字节，最少 16 字节，由包装函数把帧大小传给解释器。局部变量在 WASM locals 中，不计入该内存帧。

整个帧区放在最终字节码末尾之后，消除以前字节码超过预估区域时与帧区相交的隐患。容量为 max(1 MiB, 最大单帧)，每次分配前先检查下界，再减栈指针；不足时 trap，避免下溢和字节码覆盖。正常返回恢复调用者 SP。常量初始化的 __heap_base 不低于帧区顶部及其原始无符号值；动态初始化标记无法在构建期确定，将明确报错，最终全局节会重新编码。

新回归：**27 类、81 次构建、297 次原版/保护版对比全部通过**。覆盖四种数值类型、1024 字节边界、超过 16 KiB 的操作数栈、300 个调用返回值、混合多返回值、递归、分支峰值、重复调用和堆标记。另有 **9 次独立新实例的耗尽检查**确认 trap，且字节码未改变；这部分不冒充与原版资源上限相同。

## 再合并重复处理器

只共享普通指令处理器。完整键包含原始指令字节、出入栈类型和重映射后的操作数，因此不同局部变量或函数索引不会误合并。分支、清栈和返回处理器不参与。

代表处理器在整个模块中保持稳定，后续函数不能替换前面函数已引用的代表。只替换等宽的一字操作码，不改变字节码长度和分支偏移。instruction_expansion_factor 默认 1；3、64 等值可保留多份代表，已加入跨 64 个函数的回归。该配置之前的实现被注释，本次实际启用。

共享专项：两个种子、因子 1/3/64，**6 次构建、3456 次输出对比及双验证器通过**，并验证保留更多代表时产物增大。

## 体积与性能

MD5 两侧均保护函数 [0,1,2]，最后的地址访问器都不保护，以保持相同范围；另有默认保护全部原函数的三种子摘要回归。Base64 两侧保护全部 34 个原函数。

| 示例 | 基线字节 | 本次字节 | 减少 | 处理器数量 |
|---|---:|---:|---:|---|
| md5 | 5257 | 4413 | 16.1% | 71 → 41 |
| base64 | 75465 | 49690 | 34.2% | 927 → 216 |

7 轮交替构建中位数：MD5 约 6.25 → 6.22 ms；Base64 约 92.34 → 82.89 ms。本机结果存在波动，不据此推及所有模块。

MD5 运行基准先做 132 次摘要校验，然后对五组输入交替测量 7 轮。本次相对基线约 0.97～1.04×，**基本持平，没有显著运行加速结论**。本轮主要收益是修复数据覆盖、减少处理器及输出体积。未测量或证明相同抗分析强度。

## 仍存在的范围限制

本轮没有实现与业务内存隔离，仍使用同一线性内存，不能消除原有内存容量和越界行为差异。共享内存/多内存/memory64/引用/SIMD 等支持范围不变。

帧区是有界资源，过深调用会 trap。WASM trap 会跳过已分配调用者的正常 SP 恢复；与原实现一样，**trap 后不保证该实例的私有 SP 已复原，应丢弃该实例并重新实例化**。耗尽测试每次使用新实例，没有将 trap 后复用计为通过。大量深栈 AST 的构建内存消耗也不在本轮优化范围。
